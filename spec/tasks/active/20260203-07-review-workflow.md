# Task: Article Review Workflow

## Purpose

After deduplication, researchers need to review individual articles with AI agents and/or human reviewers. This feature provides:

1. **Review file management**: Generate and maintain YAML files for recording assessments
2. **Progress tracking**: Show review status (pending, conflicting, finalized, etc.)
3. **Collaborative workflow**: Extract subsets for distributed review, then merge results
4. **Final export**: Export only included articles for downstream processing

### User Story

As a systematic review researcher, I want to:
- Record multiple assessments (AI and human) for each article
- Track which articles need attention (unreviewed, conflicting opinions)
- Distribute review work to multiple reviewers via extracted files
- Merge completed reviews back into the main file
- Export final included articles for reference management

## Data Structures

### Review (individual assessment)

```typescript
interface Review {
  reviewer: string;                              // "gpt-4o", "claude-sonnet", "human:tanaka"
  decision?: "include" | "exclude" | "uncertain";
  comment?: string;
  timestamp: string;                             // ISO 8601
}
```

### ArticleEntry (article with reviews)

```typescript
interface ArticleEntry {
  // Identifiers (at least one required for matching)
  doi?: string;
  pmid?: string;
  scopusId?: string;
  arxivId?: string;
  ericId?: string;

  // Bibliographic info (for reviewer reference)
  title: string;
  authors?: string;
  year?: string;
  abstract?: string;

  // Deduplication tracking
  mergedFrom?: Array<{
    source: string;      // "pubmed", "scopus", etc.
    pmid?: string;
    doi?: string;
    scopusId?: string;
    arxivId?: string;
    ericId?: string;
  }>;

  // Review data
  reviews: Review[];
  finalDecision?: "include" | "exclude";
}
```

### ReviewFile (top-level structure)

```typescript
interface ReviewFile {
  sessionId: string;
  criteria?: string;           // Path to inclusion criteria file
  articles: ArticleEntry[];
}
```

## CLI Commands

### review init

Generate `reviews.yaml` from deduplicated search results.

```bash
search-hub review init --session <id>
```

- Loads all results from session
- Deduplicates with `mergedFrom` tracking
- Generates `reviews.yaml` with empty reviews arrays
- Copies schema file to `.search-hub/schemas/` if not exists
- Adds schema reference comment to YAML

### review status

Show review progress summary.

```bash
search-hub review status --session <id>
```

Output:
```
Review Progress: my-session
  Total:        150
  Pending:       45  (no reviews)
  Conflicting:   12  (reviewers disagree)
  Needs Final:   38  (reviewed but no finalDecision)
  Finalized:     55  (include: 32, exclude: 23)
```

### review list

List articles with optional filtering.

```bash
search-hub review list --session <id> [--filter <type>] [--format json]
```

Filters: `pending`, `conflicting`, `needs-final`, `finalized`, `all` (default)

### review extract

Extract subset to separate file for distributed review.

```bash
search-hub review extract --session <id> \
  --filter pending,conflicting \
  --sort year \
  --limit 50 \
  --offset 0 \
  -o work/batch1.yaml
```

Options:
- `--filter`: pending, conflicting, needs-final (comma-separated)
- `--sort`: year, title, random, none (default: none)
- `--limit`, `--offset`: Pagination
- `-o, --output`: Output directory or file

Output includes:
- `batch1.yaml` with schema reference
- `review.schema.json` copied alongside

### review merge

Merge edited file back into main reviews.yaml.

```bash
search-hub review merge --session <id> work/batch1.yaml [--dry-run]
```

Merge rules:
- `reviews[]`: Append (skip if reviewer+timestamp already exists)
- `finalDecision`: Overwrite with extracted file's value
- Identifiers/title: Used for matching, not updated

### review export

Export articles based on final decision.

```bash
search-hub review export --session <id> --only included [--format yaml|json|jsonl]
```

## Progress Classification

| Status | Condition |
|--------|-----------|
| `pending` | `reviews.length === 0` |
| `conflicting` | `reviews` contain different `decision` values |
| `needs-final` | `reviews.length > 0 && !finalDecision` |
| `finalized` | `finalDecision` is set |
