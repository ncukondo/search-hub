# Task: Query Iteration Log

## Purpose

During iterative query refinement, users run `search --count-only` or `search --preview` to check hit counts before executing a full search. When results are clearly inappropriate (too many, too few, wrong distribution), there is no way to record that assessment because these modes do not create sessions, and the existing `notes assess` command requires a session-id.

This task adds:
1. **Automatic logging** of `--count-only` / `--preview` results to a log file alongside the query file
2. **`query assess`** command to record structured assessments tied to the query
3. **`query log`** command to view the iteration history

This provides an audit trail of the query refinement process, which is important for systematic review methodology (PRISMA reporting) and for reconstructing the rationale behind search strategy decisions.

## Design

### Log File Naming

For a query file at `{dir}/{basename}.yaml`, the log file is `{dir}/{basename}.search-log.yaml`.

### Log File Format

```yaml
# Search iteration log for my-search.yaml
# Auto-generated by search-hub. You can also edit this file manually.

- date: "2026-02-16 10:30"
  type: count
  query_hash: "abc123"
  counts:
    pubmed: 50000
    scopus: 42000
  total: 92000

- date: "2026-02-16 10:35"
  type: assessment
  verdict: reject
  comment: "Too broad, need more specific MeSH terms"
```

### Entry Types

- `count` — Auto-recorded by `search --count-only`. Fields: `query_hash`, `counts` (provider→count map), `total`
- `preview` — Auto-recorded by `search --preview`. Fields: `query_hash`, `counts`, `total`, `titles` (provider→string[] map)
- `assessment` — Recorded by `query assess`. Fields: `verdict`, `precision`, `comment` (all optional, at least one required)

### CLI Commands

```bash
# Assess
search-hub query assess <query.yaml> --verdict reject --comment "Too broad"
search-hub query assess <query.yaml> --verdict good --precision "~60%"

# View log
search-hub query log <query.yaml>
search-hub query log <query.yaml> --json
```

## Notes

- Reuse the text-append strategy from `notes.ts` for appending entries (YAML-aware but simple)
- The `query_hash` should use the same hashing mechanism as `SessionFile.query.hash` for consistency
- Log files are intentionally human-editable (same philosophy as `notes.yaml`)
- `--count-only` with `--db` (direct query, no query file) does NOT create a log entry since there is no query file to attach it to
- Preview `titles` in the log should be stored compactly (e.g., max 5 titles per provider) to avoid log bloat
- Future enhancement: `query log --summary` to show only assessments, not every count
