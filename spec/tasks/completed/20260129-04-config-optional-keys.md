# Task: Support Optional Config Keys in CLI

## Purpose

The `search-hub config` command cannot display or set optional configuration fields such as
`providers.pubmed.email`, `providers.pubmed.api_key`, and `providers.scopus.inst_token`.

This happens because:
1. These fields are defined as `z.string().optional()` in the Zod schema (no default value)
2. `ProviderConfigSchema.parse({})` omits optional fields with no default from the result object
3. `viewConfig` uses `flattenObject` which only iterates existing object keys
4. `setConfigKey` uses `getNestedValue` which returns `undefined` for missing keys, rejecting them

Users must manually edit the TOML file to set `email`, which blocks PubMed from working out of
the box (NCBI requires an email for E-utilities).

## Notes

- Changing `optional()` to `default("")` may affect other code that checks for `undefined`
  to determine if a field is configured. Search for usages of `config.providers.*.email`,
  `config.providers.*.api_key`, and `config.providers.*.inst_token` and update checks
  from `=== undefined` to `=== ""` or `!value`.
- The TOML file generated by `search-hub init` already includes `email = ""`, so this change
  aligns the schema with the init output.
